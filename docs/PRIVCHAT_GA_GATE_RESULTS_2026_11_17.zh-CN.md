# MsgTrans 2.0.0 正式版三道门禁复验

2026-11-17，Asia/Singapore。此次没有发布、打 tag 或改变版本号。

## 1. 真实业务红项

隔离 PostgreSQL 16、Redis、签发 TLS/JWT 的临时密钥、固定 SPKI pin、32 字节附件加密密钥。服务端上传控制面与静态存储读面分开，静态服务读的是真实后端写出的对象；Prometheus 从文件服务的 `/metrics` 读取，没有启用假的指标端口。两套传输顺序执行，测试库和服务实例与故障长稳隔离。

| 原共同失败 | 复现、修复及复验 |
| --- | --- |
| 9、42、44、45、46：文件上传、附件 Outbox、保真与重发 | 缺密钥、下载 URL 错指向控制面；隔离环境补齐。附件重发改用授权 `file/get_url` 验证独立引用指向同一对象；明文摘要判重有/无密文缓存均零正文上传；新内容必上传一次正文。SDK 将完成计数移到内置分片和 S3 的共享层，修正缩略图误计和 S3 漏计，真实运行覆盖内置分片。 |
| 18：黑名单 | 服务端 check/list/remove 改用认证上下文的用户 ID，与 add 一致。验证了伪造 owner 不可读/移除他人的条目，且正常 remove 后查询确实消失。 |
| 22、24、31：typing、presence、Room | 测试用当前 wire 通道类型 Direct=1、Group=2、Room=3，不使用数据库编号；保留 typing 限频、presence 推送对账、Room 3/3 收广播和 ticket 校验。 |
| 27、28、32、33、35、37、41、47、49 | 旧黑名单无法移除，离线差量遇到阻断提前退出，污染后续已认证状态。修复根因后按原顺序跑完整用例，离线差量、好友名、恢复、未读、管理员撤回、好友流程、文本 Outbox、群已读、自资料均通过；不绕过会话状态断言。 |
| 29：群标题 | 无群名的合成群原本没有任何成员名来源。现在给合成群成员别名，并精确断言按该别名回退，不要求 SDK 返回脱离 UI 本地化契约的通用标题。 |
| 34：管理员在线推送 | 使用实际指标端点，保留计数差分与在线投递断言。 |

复跑中还发现登录提醒用例仅等待实体 bootstrap，不能保证时间线已经加载；现走 SDK 的系统频道差量同步，并要求消息属于本次登录时段。

两轮均启用证书验证并强制单传输：**各 44 项实际通过、0 失败、5 跳过**，包含原 20 项全部通过。Harness 原始摘要把 5 项 opt-in skip 计入 PASS，不能写成 49 项实测全过。未运行的是平台 Bot/系统账号/助理的 4 项选配业务以及另需零天读详情保留窗口的 1 项。隔离平台库已跑迁移，但本轮没有取得能签收这 4 项联动的独立结果，不能把它们标为通过。

## 2. 传输故障长稳

- 时间：09:58:51 至 10:58:51，单调时钟 **3,600.15 秒**，客户端正常退出并在 10:58:53 验证原 UDP 端口可重绑。
- Release 业务负载：24 个已认证 SDK 连接，8 个业务组，每组三客户端。每条成功需经历真实业务 RPC，接收方 SDK 本地库按 canonical server message ID 校验消息和正文。每次恢复还要求该组全部三会话回到 Authenticated。
- 12 次重复循环：单向 35–55 ms 延迟、独立随机丢包 3%，双向 UDP 黑洞期间保留 TLS/TCP，然后整服 SIGINT 停启（预设停服 5 秒，重开后回到 QUIC）。不是生产规模吞吐基准或不重启的服务端内存长测。
- 故障窗口外 **0 次**操作失败。共确认 **23,079 条**送达且落库；故障窗口内 **212 次**操作失败被记录，不能表述为无中断或零失败。SDK 日志共记录 **576 次**自动重连成功；服务端记录 312 个 QUIC 和 288 个 TLS/TCP 会话，与 24 个初始连接加 24 轮恢复吻合。
- 每 15 秒采资源，共 240 组采样。服务端 RSS 峰值约 36.7 MiB，FD 峰值 86；每个 SDK 进程结束前均为 34 FD，期间峰值 34–35，RSS 峰值约 35.8 MiB。12 次重启加最终关闭 **13/13 clean**，剩余会话 0、监听任务结束、许可全部归还。

| 故障 | 业务组恢复 | 最快 | p50 | p95 | 最慢 |
| --- | ---: | ---: | ---: | ---: | ---: |
| UDP 黑洞 | 96/96 | 21.41 s | 25.14 s | 27.08 s | 27.52 s |
| 整服停启 | 96/96 | 9.70 s | 9.91 s | 10.40 s | 10.86 s |

恢复时长从注入到首次确认落库且本组全部会话已认证，含约 0.5 秒的采样粒度，不能当作单连接握手耗时或产品 SLO。弱网窗口业务送达成功样本 p95 为 489 ms，含业务 RPC 和本地库轮询。长稳在附件计数修正前启动；长稳负载只发文本，没有执行后续改动的附件上传路径，网络、认证、重连与服务端代码及归档 MsgTrans 均与最终复验一致。

**裁决：** 本轮定义的长稳门禁通过。25 秒量级的黑洞恢复依然是 UI 通讯体验的重要指标；本轮没有修改超时策略，也没有宣称更严格的业务恢复目标已达成。
